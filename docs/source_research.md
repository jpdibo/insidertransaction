# Source Research

Version `research-1`, checked 07 September 2026. `config/sources.yaml` is the machine-readable registry; this report explains the evidence standard.

Sweden's FI page was fetched live. It confirms automatic publication on receipt, no pre-publication review, continuous updates, search by issuer/person/transaction/publication dates, revised/history states, Excel export, current records from 03 July 2016, older stored data to 1995, and explicit anti-abuse search limiting. This establishes a publication route, not an automated retrieval contract or live adapter.

The FCA NSM guidance was fetched live. It confirms storage of UK MAR Articles 17-19 disclosures, automatic receipt of PIP announcements, free search/download/CSV export, corrections retaining prior versions, a migration mapping for 2009-05 April 2020 history, and that NSM is not real time or a substitute for PIP public dissemination. It documents a PIP-to-NSM schema/API, not a public ingestion API.

NewsWeb was inspected in a browser. Message `681721` was classified `MANAGERS’ TRANSACTION`, displayed publication time, issuer, markets, one attachment and a human-readable transaction. The web application made an observed POST to `https://api3.oslo.oslobors.no/v1/newsreader/message?messageId=681721`; this is recorded as observed and undocumented, not represented as a supported API. The captured JSON SHA-256 is tracked in `raw_objects` after ingestion. Currency is absent from the body and remains unknown pending attachment retrieval.

Other routes came from authority/exchange publication pages listed in the registry and matrix. Transaction-level samples, pagination, caps, correction semantics, terms and attachment completeness remain unverified. Submission URLs are kept separate. Major-holdings, buyback and voting-rights routes are explicitly not substitutes.

No source has a resolved derived-data commercial licence. Public readability is not treated as permission to bulk retrieve, archive, redistribute or resell. No access control was bypassed and no endpoint/category code was invented.

## Research Update: 08 September 2026

- Germany archive: Unternehmensregister capital-market search uses `publicationCategory=80`, a token from `GET /api/search-token`, Next.js/RSC navigation, and opaque publication payloads. Payloads change on every query and must not be used as identities; the fetched detail exposes a stable official `jobNumber`. Bounded coverage across 19-23 December 2016 retains 93 publications. German, English and numbered Article 19 layouts parse without quarantine and independently pass 50/50 evidence review. Legacy aggregate labels are semantically reversed/ambiguous in some publications, so raw values are retained while normalized quantity/price and analytics eligibility remain null/false. German and English publications remain separate because no machine-readable equivalent-publication identifier is exposed.
- France: AMF BDIF exposes `/back/api/v1/informations` with `DateDebut`, `DateFin`, `TypesInformation=DD`, `From`, and `Size`; unbounded totals cap at 10,000. The adapter therefore partitions by day and validates every page count before fetching exact official PDFs.
- Switzerland: SIX exposes `/sheldon/management_transactions/v1/overview.json` and `issuers.json`. Production UI code confirms `YYYYMMDD` dates, zero-based pages, transaction codes 1/2/3, security codes 2/4/5/6/7/99, management role codes 1/2/3, and related-party codes `I`/`L`.
- United Kingdom: real-time discovery must come from an approved PIP/RIS. FCA NSM is appropriate for delayed archive reconciliation, but public automation is undocumented/restricted and needs permission.
- Netherlands: AFM exposes an unpaginated filtered XML export at `/export.aspx` with `DateFrom`, `DateTill`, register type `0ee836dc-5520-459d-bcf4-a4a689de6614`, and `format=xml`. Stable notification identity is `meldingid`; detail HTML supplies fills and official aggregates with Dutch labels/decimal formatting even on the English page. A 1 September 2026 sample discovered 18 notifications and repeated with 18 unchanged, producing 19 reconciled groups. XML-only PCA linkage is persisted with each source record for deterministic saved-byte reparse. No correction/version field is published. AFM permits copying/distribution with explicit source acknowledgement, but automation terms remain unresolved.
- Denmark: Finanstilsynet's public OAM exposes a backend JSON search with a 100-row maximum, date/category filters, exact counts, stable numeric announcement IDs, JSON details and official blob attachments. The public category represents issuer announcements; direct manager/PCA submissions are not themselves public. A 6-8 September sample retained seven announcements and accepted six; `300014006` lacks its public transaction form while correction `300014007` includes it. OAM terms contemplate download/use at user risk, but commercial redistribution and GDPR basis remain unresolved. Nasdaq is reconciliation-only without permission.
- Finland: the Nasdaq-operated OAM uses category `66` and contains 25,558 observed manager-transaction releases from July 2016 through 8 September 2026. A bounded OAM/Nasdaq comparison reconciled all Finnish-home-state regulated-market issuers; Nasdaq-only Tallink records correctly belong to Estonia. Nasdaq's May 2026 terms explicitly prohibit automated or manual capture/extraction without written approval, so no adapter was enabled. First North is outside Finnish OAM scope.
- Remaining rollout priority: Netherlands AFM bulk CSV/XML; Finland and Denmark Nasdaq Nordic JSON plus national OAM reconciliation; Belgium FSMA; then Austria, Spain, Greece, Ireland, Italy, Poland and Portugal after each route has a captured contract and completeness test.
